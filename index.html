REDSecret · AI Agent 隐写通信工具

在线可玩已开源
纯浏览器端 JS（零依赖、零服务器）· MIT License · 2026.05-06
针对「Agent 间安全传递结构化信息」与社交隐蔽表达需求，设计并实现三种隐写方案：LSB 像素隐写（3 通道 RGB 逐位交错，像素级不可见）、QR 角标隐写（抗 JPEG 与社交平台有损压缩）、零宽字符隐写（Unicode 零宽字符藏于普通文字，肉眼完全不可见）。自定义载荷格式（magic header + 版本 + 长度 + 校验和），XOR 流加密。
外部只依赖 qrcode 与 jsQR 两个通用库——隐写与加密逻辑全部自研：自定义 magic header + 3 通道交错 LSB 提取 + 4 变体零宽映射，这套组合在公开仓库里没有第二份实现。
一次主动的重写：它最早是 Python 版，后来我重写成纯浏览器版（commit 里能看到 chore: remove legacy Python scripts (now browser-only)）——浏览器端零依赖、零服务器、数据不上传，才符合隐私定位。仓库 15 个 commit 全是我一个人，无 fork。
硬指标：经 24+ 种攻击算法测试未被破解；适配微信朋友圈/小红书/飞书的图片压缩场景，解码成功率 95%+。
两支宣传片均由自建的 huashu-motion 动效管线生成——和视频里演示的工具一样，产出它们的管线也是自研的。
硬数据：隐写对比实测 diff 均值 0.0012/通道；payload 区约占 1/3 行，不宣称全图逐像素无差。

「像真人在画」· 作画顺序分层管线与验收闭环

规范 + 验收成片可播
调研规范 v1 + annotation v2 数据格式 + spike 任务包 + 6 条可执行验收标准 · 2026.11.01-02
白板动画做出来总被说「不像人在画」。我的第一动作不是调参数，而是去查各流派的共识：素描（Loomis / Proko）7 层、油画 underpainting 5 层、水彩「浅→深、永不动深色区」一条铁律、NPR 论文四篇（Haeberli 1990 / Litwinowicz 1997 / Secord 2002 / 语义驱动 painterly）。四条完全不同的路径收敛到同一件事——低频大形先、高频轮廓后；人类作画是「时间分层」，不是「空间分块」。我们旧的两版恰好各栽一边：分区域画有章法但「分块跳」，全画布连续爬（serpentine）没有分块感但也没有章法感。
最关键的一次判断是「不让 AI 画阶段图」。让模型生成"起稿→铺色→刻画"四张阶段图，四张必然不是同一张画，结构一定漂；外部引擎已经实测过这条路——终点塌，只剩约 35% 还原。我改成一张完成图 → 程序化深度切片：第 k 层是前 k 层的并集，于是 L1⊆L2⊆L3⊆L4 且 L4 = 原图。层间零漂移是数学性质而不是调参结果，「终帧锁定原图」这条红线因此天然成立。 
# annotation v2：每个「深度层」= 一个 element，region 全画布，reveal 时序接力
{ "elements": [
  {"id": "L1-construction", "reveal": {"startMs":   500, "durationMs": 6000}},  # 构图·大形
  {"id": "L2-outline",      "reveal": {"startMs":  7000, "durationMs": 7000}},  # 轮廓·五官
  {"id": "L3-shading",      "reveal": {"startMs": 14500, "durationMs": 6000}},  # 明暗·衣纹
  {"id": "L4-details",      "reveal": {"startMs": 21000, "durationMs": 8000}}   # 细节·收笔
]}
# 约束（写进验收，逐像素断言，不靠眼看）：L1⊆L2⊆L3⊆L4 且 L4 与原图 diff=0
这一步的实现我没有自己做，而是做成一份可验收的 spike 任务包交出去：两张锚点图 + anchor.sha256（防止交付方改锚点充数）+ 我自己先跑通的 baseline-slicer.py + 三条候选配方（A：Sobel 梯度分位 / D：骨架提取构造层 / E：多尺度形态学轮廓）。任务单里直接写着我实测出来的结论，省得对方走弯路——方案 A 的嵌套与锁定全 PASS，但它的 L1 在 vision 验收下只是「浅淡阴影区」：梯度弱 ≠ 结构弱，主任务做 E，A 只作对照组。6 条验收标准全部可执行：逐像素嵌套、L4 diff=0、墨区覆盖率 50/75/92（±5pp 且单调）、contact sheet 深度递进、指定环境直接可跑、anchor 哈希未变。
交付回来 6 条全 PASS：覆盖率实测居酒屋 47.1 / 73.8 / 91.4、人像 50.1 / 75.1 / 92.1（最大偏差 3.4pp），嵌套违反 0 像素，两次运行逐字节一致。报告里还主动附了一条我没写进验收项的坏消息：换「引擎自适应阈值」口径统计时，层间残差占画布 5.8%，是两种「墨」定义的数学不可两全，不是 bug。这种交付质量是任务单里那条「禁美化语义自评、宁 null 不编」的红线换来的。
落地成片 3 支：居酒屋与人像走素描四层（29 秒），哥特那支按规范里的油画路径自适应成另一套四层——铅笔起稿 → 暗部铺大关系 → 中间调 → 亮部与细节（34 秒）。同一套 schema 装得下素描和油画两种媒介顺序，说明分层不是我为某一支视频写的临时编排，是可复用的结构。验收脚本共 5 个，全部打在成片上而不是打在参数上：从成片抽定格、末帧与原图墨覆盖率对齐、分时段检查画面中央有没有按序上墨、逐 0.5 秒采样检测画面停滞（连续两点差 < 0.05pp 判"不动"）。

一次真实事故，以及我改了什么

10-18 渲染帧并发抢写：渲染任务产出异常，输出帧损坏。排查时先怀疑渲染逻辑本身（参数、素材、时间线对齐）——单独跑正常，排除；再怀疑资源不足——监控显示有余量，排除；回头看进程表发现僵尸进程残留并持有帧文件写句柄，定位到并发抢写。

恢复：pkill 清理僵尸进程后重渲。但恢复不是终点——我随后加了 1830 帧硬校验：渲染完成后逐帧校验，任意一帧损坏即判定失败并重试。

产品判断

工具谁都能用。我更想说明的是我在什么地方做了判断、为什么这样判断——这五件事是我这一年最核心的学习。

① 副驾产品：真问题不是「没有回复」，是「打断」

起点是一句用户抱怨：「复制粘贴很打断对话」。当时最直觉的方案是做成实时语音转写 + 自动回复。但我判断真正的痛点是打断而不是缺失——用户要的是不被打扰地继续对话。

所以我选择让识别全程留在本机（Vision OCR 本地推理），并且只在用户主动点击时才触发分析。这让隐私从「一个加分项」变成了「这个产品能不能被用」的前提。代价是响应变慢了，我接受这个代价。

② 内容栏目：用产品结构解决合规问题，而不是加免责声明

「AI 预测比赛结果」天然存在博彩合规风险。加免责声明是最省事的做法，但会持续消耗用户的信任。我改成两个 AI 给出不同结论的对抗结构——「东方玄学」对「西方数据」——冲突本身就是内容，而双 AI 天然不导向任何单一下注结果。

合规从「事后修补」变成了「产品结构的一部分」。这让我意识到：很多风险可以在设计阶段就消解掉，而不是在上线后打补丁。

③ 故障排查：把猜测换成可证伪的对照实验

LLM 中转服务间歇性返回 499 / 超时。我不猜，而是把可能原因拆成三项，各自设计一个能推翻自己的对照实验：① 同模型直连官方端点、绕过中转，比首 token 延迟基线 → 证伪"模型时延变长"；② 多个中转服务商跑同一请求同一 prompt 对比 → 排除"协议/端点共性问题"；③ 观察 499 出现与自身并发数的相关性，降并发重试 → 定位到并发限流。

修复分三层：退避重试 → 切备用中转并降并发 → 降级路径（缓存数据 + 模板化简报）继续完成任务并在产物标注降级。这条路径后来固化进系统工具调用层，成为所有技能共用的失败处理策略。

做 AI 产品的门槛，一半在「懂业务」，另一半在「知道模型和基础设施的真实边界在哪」。后者不能靠看文章，只能靠动手踩过。

④ 竞品分析：做成可复查的取证，而不是写一段观点

要证明「我们的历法口径和别家不一样」，最省事的做法是写一段主观对比。我给 Agent 下的是一份取证任务单：固定 3 个测试生日——常规案例 / 农历闰四月的归属 / 乌鲁木齐真太阳时换算后是否换日——逐家照抄它的排盘结果，以及页面上关于闰月、早晚子时的原文说明。红线写死：只抄不评、禁止注册、禁止付费、禁止留个人信息、站点打不开就记 BLOCKED 换下一家、截图存不全宁可少交一家也不许补拍。

跑完 5 家候选站点，3 家完成匿名排盘取证，13 张结果截图 + 6 份抄录全部存档。于是「同一个生日在两家排出不同结果」成为可以现场打开截图核对的事实，而不是我的说法。产品文案里我也只陈述自己做过的事——「真太阳时与子时换日已按锚点案例实测校验」，不点名任何一家。

⑤ 商业模型：先看头部玩家怎么赚钱，再决定自己抄什么

这个赛道的头部是 GitHub 上的 OURANIC（★11815 / fork 2325，2026-10-31 基线）：TypeScript 自研排盘引擎 MIT 开源，配套数据集 67.5 万盘 × 13 维 = 877 万段（CC BY 4.0）；变现不在开源侧，而在自己站点的 AI 解读收费。全网挂 ziwei-doushu 标签的 176 个仓库里它是源头，下游直接基于它建站。我的读法：开源是获客漏斗，钱在「解读层」——所以排盘这一层必须准、必须免费。

顺着这条线我还做了两件判断：
一、它的 13 维断语我不搬运。那是传统算命话术，会撞我自己定的「不预测吉凶」产品红线——数据集虽标 CC BY 4.0，其中原话库部分仍是非商用。
二、它开源引擎里有 3 个截至建档仍未关闭的 issue（真太阳时经度没接进主排盘函数、晚子时换日未按真太阳时判定、四化加分项查了不存在的星名）——恰好是我方实测已经覆盖的三条口径（iztro 双引擎校验 + 锚点案例全过 + 21 项 gate 全绿）。这就是差异点，写进文案但不点名。

而且这不是一次性看完就算：我挂了一条每周巡检任务盯它的 star 周涨幅（周涨 > 30% 即标记注水嫌疑）、issue 关闭、新版本、定价变动，有事推到飞书，无事回一条 [SILENT] 不打扰——竞品情报要做成常态能力，不是面试前突击。

我不认为懂业务和懂 AI 是两件事。以下是我在业务侧的真实积累——它决定了我知道哪些环节值得被 AI 改造。
